Fancy indexing copies

a = np.arange(12, dtype=np.int64).reshape(3, 4)
selected = a[[0, 2]]
selected[0, 0] = -100
assert a[0, 0] == 0
print("Original strides:", a.strides)
print("Transpose strides:", a.T.strides)

a[[0, 2]] is new data

Integer-array and Boolean reads copy, so a[0, 0] stays 0.

Strides are byte jumps

(32, 8): 32 bytes to the next row, 8 to the next column.

.T swaps the strides

Same bytes, new steps (8, 32), and no longer C-contiguous.

Advanced indexing, meaning an integer array like a[[0, 2]] or a Boolean mask, cannot be described as a regular step through memory, so reading it returns a copy. Changing selected therefore leaves a untouched, which the assert proves. Assignment is different: a[mask] = value writes directly into a. That is why chained indexing such as a[mask][0] = 5 silently does nothing to a: the first indexing step already made a copy. Strides are the number of bytes to jump to move one step along each axis. Each int64 is 8 bytes and each row has 4 of them, so moving down a row jumps 32 bytes. The transpose simply swaps the strides to (8, 32) without moving any values, which is why it is no longer C-contiguous.
