Step 2 · Preserve small changes

Tiny changes vanish in 1 + x

tiny = 1e-16
print("Naive log:", np.log(1 + tiny))
print("log1p:", np.log1p(tiny))
print("Naive exp change:", np.exp(tiny) - 1)
print("expm1:", np.expm1(tiny))

Naive log: 0.0
log1p: 1e-16
Naive exp change: 0.0
expm1: 1e-16

1 + 1e-16 rounds to 1.0

It is below float64 epsilon, so the change is lost before log runs.

log1p(x) is log(1 + x)

Computed without ever forming 1 + x.

expm1(x) is exp(x) − 1

Avoids subtracting two nearly equal numbers.

NumPy course · 13 Numerical stability

5

Cancellation happens when you subtract nearly equal numbers, or add a tiny number to a large one: the meaningful digits fall off the end of the 53-bit significand. Here 1 + 1e-16 is stored as exactly 1.0, so log gives 0 and exp(tiny) - 1 gives 0, even though the true answers are about 1e-16. np.log1p and np.expm1 are written to work on x directly, so they return 1e-16, accurate to full precision. Use them whenever x can be small, for example in log returns, interest rates or probabilities near zero. Try it: find a value for which float32 rounds 1 + x back to 1 while float64 does not. x = 1e-8 works: np.float32(1) + np.float32(1e-8) equals 1, because float32 epsilon is about 1.2e-7, while 1 + 1e-8 in float64 is still larger than 1.
