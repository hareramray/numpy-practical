Think of a seeded generator as a long, fixed stream of numbers, and each call reads the next stretch of it. The first two rows are the notebook's a and b: two fresh generators with seed 123 start at the same place in the stream, so both give 1, 68, 59, 5, 90 and assert_array_equal passes. The dashed row is what you get if you keep one generator, rng = np.random.default_rng(123), and call rng.integers(0, 100, 5) a second time: the state has moved on, so you read the next five values instead (values from running this exact code with the course's NumPy 2.5 setup). This is the whole Try it experiment in one picture: re-running the cell that creates rng rewinds to the start; re-running only a sampling line keeps reading forward.
