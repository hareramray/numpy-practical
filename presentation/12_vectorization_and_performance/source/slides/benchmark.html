Step 2 · Benchmark repeated runs

Time it fairly, more than once

from timeit import repeat
loop_seconds = min(repeat(lambda: squared_distance_loop(a, b), number=3, repeat=3)) / 3
numpy_seconds = min(repeat(lambda: squared_distance_numpy(a, b), number=3, repeat=3)) / 3
print(f"Python loop: {loop_seconds:.6f} seconds/call")
print(f"NumPy:       {numpy_seconds:.6f} seconds/call")
print(f"Observed ratio: {loop_seconds / numpy_seconds:.1f}x")
print("Input shape/dtype:", a.shape, a.dtype)

timeit.repeat runs each function three times per measurement and repeats the measurement three times on the same inputs. Taking the minimum approximates the least interrupted run, because background activity can only make a run slower, never faster. Dividing by number=3 gives seconds per call. The report includes the input shape and dtype, since a timing without its setup is hard to interpret. Note what the cell does not do: it never asserts that NumPy is faster. Hardware, dtype, memory layout and the library build all change the numbers, so speed is reported, not tested. Try it: repeat the benchmark for 10 values and for 100,000 values. Do not assume the same ratio: for tiny arrays the fixed overhead of each NumPy call dominates, so the advantage shrinks or can even reverse.
