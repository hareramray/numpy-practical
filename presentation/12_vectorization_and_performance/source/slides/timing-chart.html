This chart draws the two real timings from the notebook's reference run on one linear scale. The Python loop took 0.006254 seconds per call on 20,000 values; the NumPy expression took 0.000018 seconds, so its bar is only about 4 pixels wide. The printed ratio, 350.0x, comes from the unrounded timings, which is why it is not exactly 0.006254 divided by 0.000018. The speed-up comes from moving the per-element work out of the Python interpreter, where every step involves object handling and dispatch, into a compiled loop over contiguous float64 values. Treat the number as an observation of this machine and this run, never as a constant. Try it: rerun with 10 values and with 100,000 values and compare the ratios. With 10 values the fixed call overhead dominates and NumPy's advantage nearly disappears.
