NumPy course · 02 Indexing and filtering

5

Both expressions select the same four values, the second subject's scores, but they return different shapes, as the notebook's output line Shapes: (4,) (4, 1) proves. A single integer in an axis position removes that axis entirely, so scores[:, 1] is a 1D array with shape (4,). A slice, even one of width 1 like 1:2, preserves the axis, so scores[:, 1:2] is still 2D with shape (4, 1): a column. This matters later when you combine arrays, because a (4,) array and a (4, 1) array broadcast differently. Rule: use an integer when you want a value or a lower-dimensional result, and a slice when you want to keep the table shape.

Step 2 · Boolean masks

A comparison makes a mask

marks = np.array([45, 62, 78, 90, 55, 84])
mask = (marks >= 60) & (marks < 85)
print("Mask:", mask)
print("Selected:", marks[mask])
print("Positions:", np.flatnonzero(mask))
assert np.count_nonzero(mask) == 3

Mask: [False  True  True False False  True]
Selected: [62 78 84]
Positions: [1 2 5]

& | ~

and, or, not, applied element by element.

Parentheses first

& binds tighter than >=, so wrap each comparison.

Not and / or

Python's and cannot combine arrays elementwise.

NumPy course · 02 Indexing and filtering

6

A comparison such as marks >= 60 does not return one True or False: it returns a Boolean array with one answer per element. Indexing with that mask keeps the entries where it is True. To combine conditions use & for and, | for or, and ~ for not, and put each comparison in parentheses, because & has higher precedence than the comparison operators. Python's and keyword tries to turn the whole array into a single truth value and raises an error. np.flatnonzero reports where the True values are, and np.count_nonzero counts them, here 3. Try it: select marks below 50 or at least 85 with marks[(marks < 50) | (marks >= 85)]. Expect [45 90].

8

table is np.arange(12).reshape(3, 4), so each cell's value is also its position in reading order; the grey numbers are row and column indices. When you pass two integer lists, NumPy zips them into coordinate pairs: row 0 with column 1, and row 2 with column 3. You get two values, 1 and 11, not a block. To ask for every combination of some rows and some columns, wrap the lists in np.ix_, which builds a grid of indices: rows 0 and 2 crossed with columns 1 and 3 give the 2 by 2 block [[1 3] [9 11]], printed over two lines in the notebook. Ask: how many values would table[[0, 1, 2], [0, 1, 2]] return? Three, the diagonal 0, 5, 10.

The idea to remember

Slices keep shape.
Masks pick values.

Select by position with integers and slices, by condition with Boolean masks joined by &, | and ~.

Pause here. Every selection in NumPy is one of these two kinds. Position-based selection, with integers and slices, follows the shape: slices keep the axes, integers remove them. Condition-based selection, with a Boolean mask, asks a question of every element and keeps the ones that answer True, returning a flat 1D result. Knowing which kind you are writing tells you the shape of the answer before you run it.
