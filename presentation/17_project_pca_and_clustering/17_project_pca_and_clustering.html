Step 1 · Standardise

Put features on one scale

rng = np.random.default_rng(21)
centers = np.array([[-4., -3., 0.], [0., 4., 4.],
                    [4., -2., -3.]])
X = np.concatenate([rng.normal(loc=center,
    scale=0.55, size=(60, 3))
    for center in centers])
feature_mean = X.mean(axis=0)
feature_std = X.std(axis=0)
safe_std = np.where(feature_std == 0, 1, feature_std)
Z = (X - feature_mean) / safe_std
print("Observations, features:", Z.shape)

Each row is an observation and each column a feature. Distances, and therefore both PCA and k-means, are dominated by whichever feature has the largest numbers, so we standardise: subtract each column's mean and divide by its standard deviation. A constant column has standard deviation zero; np.where swaps that zero for one, so the column simply becomes zeros instead of NaN. The notebook asserts that every column of Z has mean 0 (within 1e-12) and standard deviation 1. Note the caveat: here the whole dataset is used for exploration; in a predictive workflow you fit the mean and std on training data only. Try it: multiply one raw feature by 100 and compare distances before and after standardisation; before, that feature swamps the others, after, the distances are unchanged by the rescaling.

Step 2 · PCA through SVD

One SVD gives the directions

Z = U diag(s) Vt

Rows of Vt are the principal directions.

s² is variance

Squared singular values, normalised, give each share.

Signs are arbitrary

Test reconstruction and variance, never a sign.

U, s, Vt = np.linalg.svd(Z, full_matrices=False)
components = Vt[:2]
embedding = Z @ components.T
explained_ratio = s ** 2 / np.sum(s ** 2)
reconstructed_Z = embedding @ components
print("Explained variance ratios:", explained_ratio)
print("Retained fraction:", explained_ratio[:2].sum())
print("Reconstruction MSE:",
      np.mean((Z - reconstructed_Z) ** 2))

5

PCA rotates centred data toward the directions of greatest variance. Because Z is already centred, its singular value decomposition does all the work: the rows of Vt are orthonormal principal directions, ordered by singular value, and each squared singular value is proportional to the variance along its direction. Keeping two rows compresses three features into two. The notebook asserts that U times s times Vt rebuilds Z exactly, and that the two kept components are orthonormal, components @ components.T equals the 2 by 2 identity. The sign of each direction is arbitrary, so a different machine may flip one; that is why the tests check reconstruction and variance rather than signs. Try it: keep one component, then all three. With one, the error rises to the dropped share, about 0.376 (0.3675 plus 0.008); with all three it falls to essentially zero.

Step 3 · K-means

The heart of the k-means loop

def kmeans(data, k, seed=0, max_iter=100):
    rng = np.random.default_rng(seed)
    centers = data[rng.choice(len(data), k,
            replace=False)].copy()
    for _ in range(max_iter):
        squared = ((data[:, None, :] -
            centers[None, :, :]) ** 2).sum(axis=-1)
        labels = squared.argmin(axis=1)
        # ... record inertia; stop if labels repeat
        for group in range(k):
            members = data[labels == group]
            if len(members):
                centers[group] = members.mean(axis=0)

Start from data

k distinct rows, chosen by a seeded generator.

Assign

One broadcast computes every point-to-center distance.

Update

Each center moves to its members' mean; an empty group keeps its center.

This is an excerpt of the notebook's kmeans function; the full version first validates its input (a finite 2-D table, 1 ≤ k ≤ number of rows, max_iter ≥ 1), records the inertia of every pass in a history list, breaks when the labels equal the previous pass, and after the loop reassigns once more so the returned labels always match the returned centers. K-means alternates two steps: assign each observation to its nearest center, then replace each center by the mean of its group. It minimises a local squared-distance objective and depends on where it starts, so the result depends on the seed. The if len(members) guard handles empty clusters by keeping the previous center instead of computing the mean of nothing, which would be NaN. Cluster numbers are arbitrary labels.

Step 3 · Assign, update, repeat

Two moves until nothing changes

Once

Initialise

k random rows become the first centers.

Move 1

Assign

Every point takes the label of its nearest center.

Move 2

Update

Every center moves to the mean of its points.

Repeat with the new centers

Stop

Labels equal the last pass, or max_iter is reached.

Inertia only falls

Each move can only lower the squared distances.

NumPy course · 17 PCA and clustering project

9

This is the whole algorithm. Inertia is the total squared distance from each point to its assigned center. Assigning each point to its nearest center cannot increase it, because each point picks the smallest available distance. Moving each center to its group's mean cannot increase it either, because the mean is the point that minimises squared distance to a group. So inertia never rises, and since there are finitely many labelings the loop must stop. The notebook turns this argument into a test: np.diff(history) must be at most 1e-9 everywhere. What the loop does not promise is the best answer overall: it finds a local minimum that depends on the starting rows, which is why we try several seeds.

This is the broadcasting trick from notebook 05 doing real work. Inserting a new axis with None turns the data into shape (180, 1, 3) and the centers into (1, 3, 3). Aligned from the right, the length 1 axes stretch, so the subtraction produces every point minus every center: shape (180, 3, 3), read as point, center, feature. Squaring and summing the last axis gives a (180, 3) table of squared distances, and argmin along axis 1 picks the nearest center for each point, giving 180 labels. The notebook's own warning applies: this materialises the full three-dimensional tensor, which is fine for small data but needs chunking or a more memory-efficient formula for large datasets.

Because k-means finds only a local minimum, the notebook runs it from five seeds and keeps the run with the smallest final inertia. The winner splits the 180 observations into three groups of exactly 60, which matches how the data were generated, and the history assertion confirms inertia never rose. Two small tests probe edge cases: four points forming two tight pairs must split into those pairs with inertia exactly 1.0, and four identical points with k equal to 3 must reach inertia 0, which exercises the empty-cluster guard. The plot colours each point by its label in the 2-D PCA view: three compact, well separated groups. Try it: compare k equal to 2, 3 and 4. Inertia keeps falling as k grows, so a lower inertia alone does not prove a better clustering.

The idea to remember

Test invariants,
not lucky outputs.

Signs flip and cluster numbers shuffle. Reconstruction error, orthonormal directions and a falling inertia do not.

Pause here. PCA and k-means each fit in a dozen lines of NumPy; the expertise is in knowing what must always be true of the result. A principal direction may come back with the opposite sign, and cluster 0 on one run may be cluster 2 on another, so tests that compare exact values are fragile. Tests of properties, such as an exact reconstruction with all components, components @ components.T equal to the identity, and a non-increasing history, hold on every machine and every seed.
