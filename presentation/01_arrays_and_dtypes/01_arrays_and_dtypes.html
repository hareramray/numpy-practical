      "bytes:", sales.nbytes)

[[12 15 18]

shape

The length of each axis: 2 rows, 3 columns.

ndim and size

ndim counts axes; size counts every element.

dtype and nbytes

One type for all values, and the memory they use.

NumPy course · 01 Arrays and dtypes

3

An array is a rectangular collection of values that all share one dtype. Four attributes tell you almost everything: shape gives the length of each axis, ndim counts the axes, size counts all elements, and dtype names the element type. nbytes is the memory used by the values: 6 elements of 8-byte int64 give 48. The notebook also asserts sales.shape == (2, 3) and sales.size == 6, so the cell proves its own claims. Try it: add one complete row, such as [30, 32, 35]. Predict first: shape becomes (3, 3) and size becomes 9 (and nbytes 72).

NumPy course · 01 Arrays and dtypes

5

Two constructors build sequences, and they disagree about the stop value. arange(start, stop, step) counts up by a step and excludes the stop, exactly like Python's range, so arange(0, 10, 2) ends at 8. linspace(start, stop, num) asks for a count instead of a step, and includes both endpoints by default, so 5 points from 0 to 1 are spaced 0.25 apart. Prefer linspace for floating-point grids: you control the number of points and avoid rounding surprises with a fractional step. Try it: create seven evenly spaced points from -3 to 3 with np.linspace(-3, 3, 7). You get -3, -2, -1, 0, 1, 2, 3 as floats, a spacing of exactly 1.

Step 2 · Choose a constructor

Start from known values

print("Zeros:\n", np.zeros((2, 3)))
print("Full:\n", np.full((2, 2), 7))
buffer = np.empty(3)
buffer[:] = 4.5
print("Filled buffer:", buffer)

Zeros:
 [[0. 0. 0.]
 [0. 0. 0.]]
Full:
 [[7 7]
 [7 7]]
Filled buffer: [4.5 4.5 4.5]

zeros and ones

Pass a shape tuple. The default dtype is float64, hence 0.

full

Any fill value. An integer 7 gives an integer array.

empty

Storage only, no set values. Fill every entry before reading.

NumPy course · 01 Arrays and dtypes

6

zeros, ones and full create arrays whose every value is known in advance. Their first argument is the shape, written as a tuple, so (2, 3) means 2 rows and 3 columns. Notice the dots in the zeros output: zeros and ones default to float64. full infers the dtype from the fill value, so 7 gives integers. empty is different: it allocates memory without initialising it, so the contents are whatever bytes happened to be there. That is only safe when you overwrite every entry before reading, as buffer[:] = 4.5 does here. Ask: what would print if we removed the assignment? Unpredictable values, which is the point.

Step 3 · Dtype affects results

The dtype decides what fits

prices = np.array([1, 2, 3], dtype=np.int64)
prices[0] = 1.9
print("After integer assignment:", prices)
floating = prices.astype(np.float64)
floating[0] = 1.9
print("Floating version:", floating)
print("int8 limits:", np.iinfo(np.int8).min,
      np.iinfo(np.int8).max)

After integer assignment: [1 2 3]
Floating version: [1.9 2.  3. ]
int8 limits: -128 127

Integers drop fractions

1.9 in an int64 array is stored as 1, silently.

astype converts

It returns a new array with the dtype you ask for.

Small types, small ranges

int8 holds only −128 to 127. Check np.iinfo first.

NumPy course · 01 Arrays and dtypes

7

Every array has exactly one dtype, and assigning into it converts the new value to that dtype. An integer cannot hold a fractional part, so assigning 1.9 into an int64 array truncates toward zero and stores 1, with no warning. astype(np.float64) builds a new floating-point array; the same assignment then keeps 1.9. Small integer types save memory but have narrow ranges: np.iinfo(np.int8) reports -128 to 127. The notebook asserts floating.dtype == np.float64 to confirm the conversion. Rule of thumb: use explicit floating-point arrays whenever the calculation needs fractions.

8

The same line of code gives two different arrays because the target dtype differs. In the int64 array, the orange cell received 1.9 but can only hold whole numbers, so NumPy truncated toward zero and stored 1. Truncation is not rounding: 1.9 becomes 1, not 2, and -1.9 would become -1. After astype(np.float64), the blue cell keeps 1.9, and the other values print with a trailing dot to show they are floats. This silent conversion is a common source of bugs, so check .dtype whenever a result looks too round.

Step 3 · Dtype affects results

Bytes per value, by dtype

int8

1 byte · only −128 to 127

float32

4 bytes · fractions, about 7 digits

int64

8 bytes · whole numbers

float64

8 bytes · NumPy's default float

nbytes = size × bytes per value. The sales table: 6 × 8 = 48 bytes (int64).

NumPy course · 01 Arrays and dtypes

9

Each bar is drawn to scale: one byte per 96 pixels. The dtype fixes how many bytes every single value occupies, and nbytes is just size times that number, which is why the 2 by 3 int64 sales table used 48 bytes. Smaller types save memory, but they pay for it: int8 overflows past 127, and float32 keeps fewer significant digits than float64. Choose the smallest type that safely holds your data and its calculations. Try it: compare nbytes for 1,000 values stored as float32 and float64, for example np.zeros(1000, dtype=np.float32).nbytes. Expect 4,000 bytes versus 8,000 bytes: float32 halves the memory.

The idea to remember

Shape says where.
Dtype says what.

Every array is a rectangular grid of one type. Check .shape and .dtype before you trust a result.

Pause here. When a result surprises you in any later notebook, the first two questions are almost always: what is the shape, and what is the dtype? The shape tells you how values are arranged along each axis; the dtype tells you what each value can hold and how much memory it takes. Indexing in notebook 02 and axes in notebook 03 both build directly on reading the shape.

multiples = np.arange(5, 26, 5)
