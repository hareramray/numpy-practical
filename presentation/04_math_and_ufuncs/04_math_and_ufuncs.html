Step 1 · Elementwise calculations

Operators work element by element

quantity = np.array([2, 3, 1])
price = np.array([50., 20., 100.])
revenue = quantity * price
print("Revenue by product:", revenue)
print("Total:", revenue.sum())
print("Square roots:", np.sqrt([1., 4., 9.]))
np.testing.assert_allclose(
    np.log(np.exp([0., 1., 2.])), [0, 1, 2])

Arithmetic operators on two arrays of the same shape combine corresponding entries: 2 times 50, 3 times 20, 1 times 100, giving revenue [100, 60, 100] and a total of 260. Universal functions, or ufuncs, such as np.sqrt, np.exp and np.log, apply a function to every element and return an array of the same shape. The final assert shows that log undoes exp elementwise. Revenue becomes [90, 54, 90] and the total drops from 260 to 234.

Step 2 · Conditions and clipping

clip bounds; where chooses

scores = np.array([-5, 45, 75, 110])
bounded = np.clip(scores, 0, 100)
labels = np.where(bounded >= 60, "pass", "retry")
print(bounded)
print(labels)
np.testing.assert_array_equal(
    bounded, [0, 45, 75, 100])

[  0  45  75 100]
['retry' 'retry' 'pass' 'pass']

clip(a, lo, hi)

Raises values below lo and lowers values above hi.

where(cond, yes, no)

Picks yes or no for each element from a boolean mask.

Arguments run first

np.where selects results; it does not stop an invalid calculation inside them.

NumPy course · 04 Math and ufuncs

5

np.clip limits every value to an interval: -5 is raised to 0 and 110 is lowered to 100, while 45 and 75 pass through unchanged. np.where takes a boolean condition and two choices, and builds the output one element at a time, taking the first choice where the condition is True and the second where it is False. One subtlety: Python evaluates both choice arguments in full before where selects, so where cannot protect you from, say, a division by zero inside an argument. Step 3 shows the right tool for that. Try it: use np.select with conditions bounded < 50 and bounded < 80 and a default for at least 80, to create three labels. For these scores you should get low, low, middle and high.

Step 3 · Safe division

Divide only where it is defined

revenue = np.array([100., 0., 90.])
units = np.array([2., 0., 3.])
unit_price = np.full_like(revenue, np.nan)
np.divide(revenue, units, out=unit_price,
          where=units != 0)
print(unit_price)
np.testing.assert_allclose(unit_price,
    [50, np.nan, 30], equal_nan=True)

[50. nan 30.]

out= is the buffer

Fill it first: skipped entries keep that value.

where= is the mask

Only True positions are computed, so 0 / 0 never runs.

NaN means missing

A floating-point marker for an undefined unit price.

NumPy course · 04 Math and ufuncs

7

Ufuncs such as np.divide accept two useful keyword arguments. where= is a boolean mask: the calculation runs only at True positions. out= is the array the results are written into. Positions the mask skips are never touched, so you must initialise out first; otherwise they contain whatever was there. Here the buffer starts as all NaN, NaN being the floating-point marker for a missing value, so the entry with zero units ends up as nan instead of a warning or a misleading number. Unlike np.where, this genuinely avoids the invalid calculation. Try it: build the buffer with np.zeros_like instead. The middle price becomes 0., which now reads like a real price of zero rather than "undefined", so the missing-value meaning is lost.

The idea to remember

Write it once.
Every cell obeys.

Operators and ufuncs run on every element. clip, np.where and where= decide, cell by cell, what is computed and kept.

Pause here. Everything in this notebook is elementwise: the operation is written once and applied to each position of the array. The only question you control is what happens at each cell, and the three tools answer it: clip bounds a value, np.where chooses between two values, and a ufunc's where= decides whether a value is computed at all. Broadcasting, next, extends the same idea to arrays of different shapes.
