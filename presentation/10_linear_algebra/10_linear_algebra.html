Step 1 · Matrix multiplication

@ multiplies rows by columns

A * A is elementwise

Each entry is squared on its own: 2 becomes 4.

A @ A is a matrix product

Each entry is one row dotted with one column: multiply matching entries, then add.

A @ v gives a vector

A (2, 2) matrix times a length-2 vector is a length-2 vector.

A = np.array([[1., 2.], [3., 4.]])
v = np.array([10., 20.])
print("Elementwise:\n", A * A)
print("Matrix product:\n", A @ A)
print("Matrix times vector:", A @ v)

Elementwise:
 [[ 1.  4.]
 [ 9. 16.]]
Matrix product:
 [[ 7. 10.]
 [15. 22.]]
Matrix times vector: [ 50. 110.]

NumPy course · 10 Linear algebra

3

The star operator and the at operator look similar but mean very different things. A * A multiplies matching entries, so 3 becomes 9 and 4 becomes 16. A @ A is the matrix product: every result entry is a dot product of a row from the left matrix with a column from the right matrix. A @ v treats v as a column, giving 1 times 10 plus 2 times 20, which is 50, and 3 times 10 plus 4 times 20, which is 110. The notebook confirms this with np.testing.assert_allclose(A @ v, [50, 110]). Try it: compute the first entry of A @ A by hand before looking at the next slide.

Step 1 · The shape rule

Inner sizes match, outer sizes stay

A (3, 2)

@

B (2, 4)

=

A @ B (3, 4)

(m, n) @ (n, p) → (m, p)

The inner sizes must agree (2 and 2). The outer sizes, 3 and 4, become the result's shape. The orange row times the blue column fills the one dark cell.

4

This is the one rule to check before any matrix product. For A shaped (m, n) and B shaped (n, p), the inner sizes n must match, because each row of A is paired element by element with each column of B. The result has the outer shape (m, p): one entry for every row of A and every column of B. In the diagram, the orange row of A and the blue column of B produce the single dark cell. On the right is the Try it answer: row 0 of A is [1, 2], column 0 of A is [1, 3], so the first entry is 1 times 1 plus 2 times 3, which is 7, matching the printed output. If the inner sizes disagree, NumPy raises a ValueError instead of guessing.

Step 2 · Solve equations

Solve A x = b, then check it

A = np.array([[2., 1.], [1., 3.]])
b = np.array([5., 7.])
x = np.linalg.solve(A, b)
print("Solution:", x)
print("Residual norm:", np.linalg.norm(A @ x - b))
print("Condition number:", np.linalg.cond(A))
np.testing.assert_allclose(A @ x, b)

Solution: [1.6 1.8]
Residual norm: 0.0
Condition number: 2.6180339887498953

solve finds x

For a square, full-rank A it returns the unknown vector directly.

The residual checks it

A @ x − b should be close to zero. Here its norm is 0.0.

Condition number warns

About 2.6 is small, so x is stable. Large values mean tiny input changes move x a lot.

NumPy course · 10 Linear algebra

5

A x = b is two equations with two unknowns: 2 x1 + x2 = 5 and x1 + 3 x2 = 7. np.linalg.solve finds x = [1.6, 1.8]. Never trust a solution blindly: the residual A @ x minus b measures how well the answer satisfies the equations, and its norm here is exactly 0.0. The condition number measures sensitivity. A value near 1 is ideal; nearly dependent columns push it towards infinity, and then tiny changes in b can produce large changes in x. Try it: make both rows of A identical. The matrix becomes singular, and solve raises numpy.linalg.LinAlgError, which you can catch with try and except.

6

Picture the system as a matrix A times an unknown column x giving the known column b. Solving means finding the orange cells. Substituting 1.6 and 1.8 back into both rows reproduces 5 and 7, which is exactly what the residual check measures. On paper we write x equals A inverse times b, but in code you should call np.linalg.solve: it factors A once and back-substitutes, which is less work and less rounding error than building the whole inverse and then multiplying. Try it: make both rows of A identical. The rows no longer carry independent information, the matrix is singular, and solve raises LinAlgError instead of returning nonsense. Catch it with try and except so Run All still works.

Step 3 · Least squares

Least squares fits a line

x_data = np.arange(5, dtype=float)
y_data = np.array([1.1, 2.9, 5.2, 6.8, 9.0])
design = np.column_stack(
    [np.ones(x_data.size), x_data])
coefficients, residuals, rank, singular_values = (
    np.linalg.lstsq(design, y_data, rcond=None))
prediction = design @ coefficients
print("Intercept, slope:", coefficients)
print("RMSE:", np.sqrt(np.mean(
    (prediction - y_data) ** 2)))

Intercept, slope: [1.06 1.97]
RMSE: 0.13490737563232053

Too many equations

5 points, 2 unknowns: no single line passes through them all.

A column of ones

It multiplies the intercept; the x column multiplies the slope.

Smallest squared gaps

lstsq returns coefficients first, then residuals, rank and singular values.

NumPy course · 10 Linear algebra

7

Real data rarely fits a model exactly. Here we have five noisy points and want a line y = intercept + slope times x, which has only two unknowns. Each point gives one equation, so the system is overdetermined and has no exact solution. Least squares picks the coefficients that make the sum of squared residuals as small as possible. The design matrix has a column of ones, so that the first coefficient acts as the intercept, and a column of x values for the slope. The fit gives intercept 1.06 and slope 1.97, and the root mean squared error of about 0.135 says the line misses each point by a small amount on average. The notebook also asserts rank == 2: both columns carry independent information.

NumPy course · 10 Linear algebra

9

The singular value decomposition factors any matrix into three pieces. Here the 5 by 2 design matrix becomes U, shaped 5 by 2, the singular values s, and Vt, shaped 2 by 2. U and Vt hold orthonormal directions, and s holds one strength per direction, sorted from largest to smallest. A singular value close to zero marks a direction with very little variation, which is exactly when solving or fitting becomes unstable. NumPy returns s as a 1D array, not a diagonal matrix, so the notebook rebuilds design with (U * s) @ Vt: broadcasting scales each column of U by its singular value, which equals U @ np.diag(s). The assert_allclose check, with an absolute tolerance of 1e-12, proves the factorization reproduces the original matrix, and the notebook asserts rank == 2 from the earlier lstsq call.

The idea to remember

Match the shapes.
Solve, don't invert.

Check (m, n) @ (n, p) before you multiply. For A x = b, call solve or lstsq, then check the residual.

Pause here. Almost every linear algebra bug in NumPy is either a shape mismatch or trusting a computed answer without checking it. Read the shapes before writing @. Prefer np.linalg.solve for square systems and np.linalg.lstsq when there are more equations than unknowns, and always verify with a residual or an assert_allclose.
