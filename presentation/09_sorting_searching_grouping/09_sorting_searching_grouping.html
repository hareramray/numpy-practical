Step 1 · Sort values and positions

Sort positions, keep rows aligned

names = np.array(["Asha", "Ben", "Chen", "Divya"])
scores = np.array([82, 95, 82, 70])
order = np.argsort(-scores, kind="stable")
print(names[order])
print(scores[order])
np.testing.assert_array_equal(names[order],
    ["Ben", "Asha", "Chen", "Divya"])

['Ben' 'Asha' 'Chen' 'Divya']
[95 82 82 70]

sort vs argsort

sort returns values; argsort returns the indices that order them.

One order, many arrays

Index names and scores with the same order.

Negate for descending

A stable sort of −scores keeps ties in input order.

np.sort returns the values in order, but then you lose track of whose score is whose. np.argsort instead returns the positions that would put the array in order, and you can apply those positions to any related array of the same length: here names and scores, so names stay aligned with scores. To sort from highest to lowest we sort the negated scores. A stable sort keeps tied elements in their original input order, so Asha, who comes first in the input, stays ahead of Chen at 82. Reversing an ascending result would also reverse the ties, which is why the notebook negates instead. Try it: sort scores ascending with np.argsort(scores, kind="stable"). The order becomes Divya, Asha, Chen, Ben, and the tied student who appears first is Asha, again in input order.

Step 2 · Search in sorted data

Find where a value belongs

sorted_values = np.array([10, 20, 20, 30, 40])
left = np.searchsorted(sorted_values, 20, side="left")
right = np.searchsorted(sorted_values, 20, side="right")
print("Insertion range:", left, right, "count:", right - left)
labels, counts = np.unique(["tea", "coffee", "tea", "juice"],
                           return_counts=True)
print(dict(zip(labels, counts)))
assert right - left == 2

np.searchsorted answers the question: if I inserted this value into an ascending sorted array, at which position would it go so the array stays sorted? It uses binary search, so it is fast even on huge arrays, but it silently gives wrong answers if the input is not sorted. With side="left" the new value goes before any equal values, position 1 here; with side="right" it goes after them, position 3. The difference, 2, is the number of 20s in the array. np.unique returns the distinct labels in sorted order, and with return_counts=True it also returns how often each occurs: coffee 1, juice 1, tea 2. The printed dictionary shows NumPy 2's typed scalars, np.str_ and np.int64; the output is wrapped across lines here. Try it: find the insertion point for 25. It is 3, the position of 30, which is why it is not a match: an insertion point says where a value would go, not that it is present.

An insertion position is a gap, not a cell. Five elements have six gaps, numbered 0 to 5, shown under the row. To insert another 20 while keeping order, there are two valid gaps: just before the first 20, gap 1, which side="left" returns, and just after the last 20, gap 3, which side="right" returns. Everything between those two gaps is a run of equal values, so right minus left counts the copies of 20: two. That trick counts occurrences in sorted data without scanning. Step 3 · Group totals without pandas

Group totals with codes

category = np.array(["tea", "coffee", "tea", "juice", "coffee"])
revenue = np.array([10., 20., 15., 12., 30.])
groups, inverse = np.unique(category, return_inverse=True)
totals = np.bincount(inverse, weights=revenue,
                     minlength=groups.size)
counts = np.bincount(inverse, minlength=groups.size)
for group, total, mean in zip(groups, totals,
                              totals / counts):
    print(group, "total:", total, "mean:", mean)
np.testing.assert_allclose(totals.sum(), revenue.sum())

coffee total: 50.0 mean: 25.0
juice total: 12.0 mean: 12.0
tea total: 25.0 mean: 12.5

Labels to codes

return_inverse gives each label its group number.

bincount adds

With weights it sums values per code; without, it counts.

Means = totals / counts

minlength keeps every group.

NumPy course · 09 Sort, search and group

7

This is a group-by in pure NumPy. np.unique with return_inverse=True returns two things: the sorted distinct groups, coffee, juice and tea, and an inverse array that encodes each original label as a nonnegative integer, the position of its group. np.bincount then walks through those codes: with weights=revenue it adds each sale's revenue into its group's slot, giving totals; without weights it simply counts how many sales each group has. Dividing totals by counts gives group means. Weighted bincount always returns floats. minlength guarantees one slot per group even when a code never appears. The final assert proves nothing was lost: the group totals add up to the raw total. Try it: compute each group's share of total revenue with totals / totals.sum(). You get about 0.575 for coffee, 0.138 for juice and 0.287 for tea, and the shares sum to 1.

The idea to remember

Work with positions,
not just values.

argsort, searchsorted and unique return integers. Reuse them to keep arrays aligned and to reduce by group.

Pause here. Every tool in this notebook answers with integers rather than values: argsort gives an order, searchsorted gives a gap number, unique gives group codes. Those integers are reusable. One order reorders every related array, two insertion points count duplicates, and one code array lets bincount total, count and average any column by group. Thinking in positions is what makes NumPy feel like a database without one.
